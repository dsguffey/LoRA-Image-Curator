# Git-Ready Checklist

Use this checklist before publishing or updating a public repository snapshot.
It is intentionally separate from the golden-build gate: the golden gate proves
the release behaves like a complete application package, while this checklist
protects the public repository from private data, confusing history, and
unclear project status.

## Repository Screening

- Confirm the public version agrees in `app_identity.py`, `VERSION.txt`,
  `pyproject.toml`, launchers, `README.md`, `README.txt`, `CHANGELOG.md`, and
  `ROADMAP.md`.
- Confirm `RELEASE_MANIFEST.sha256` was regenerated by `tools/build_release.py`
  from the exact source tree being published.
- Run `python tools\audit_project.py` and resolve any private-path, credential,
  forbidden-artifact, documentation, subprocess, dynamic-evaluation, or SQLite
  ownership findings.
- Confirm the dependency-free GitHub Actions workflow passes after the first
  push. Hosted checks do not replace provider, GPU, or live-Windows Tk testing.
- Check that no private catalogs, SQLite backups, image datasets, thumbnail
  caches, logs, exported datasets, model weights, virtual environments, local
  archives, or dependency snapshots are staged.
- Check that screenshots, if added later, show synthetic or permission-safe
  images only.
- Keep old ZIPs, handoffs, smoke-test outputs, and personal QA notes out of the
  public repository unless they have been deliberately rewritten for public use.

## Publication Readiness

- Confirm `README.md` states the current status honestly as a pre-1.0 active
  development project.
- Confirm `BUGS.md` separates LoRA Image Curator defects from third-party
  provider/tool/model limitations.
- Confirm `ROADMAP.md` lists the current milestone, next milestone, and deferred
  risky QA work without implying it has already passed.
- Confirm `THIRD_PARTY_NOTICE.md`, `MODEL_LICENSES.txt`, and `SECURITY.md`
  explain provider ownership, dependency trust boundaries, and local-first
  privacy limits.
- Confirm `LICENSE` is present and the README does not imply bundled rights to
  third-party model weights, FFmpeg, PyTorch, Transformers, InsightFace, ONNX
  Runtime, or MediaPipe.

## Verification Commands

Run the full golden gate on Windows before tagging or calling a ZIP golden:

```powershell
python -X dev -m tests.test_golden_build
```

For a quick pre-commit sanity pass when the GUI gate is not needed:

```powershell
python -m tools.compile_project
python tools\audit_project.py
python tools\build_release.py
```

The `--no-gui` golden mode is useful for headless development confidence, but it
does not replace the live Windows GUI gate.

## Suggested Public Positioning

Use wording like:

> LoRA Image Curator is a pre-1.0 local Windows desktop application for managing
> image datasets used in LoRA training workflows. It is actively being
> stabilized and has been stress-tested with roughly 14,000-17,000 local images.

Avoid presenting this snapshot as finished commercial software. The strongest
public framing is an active engineering portfolio project with transparent
limitations, real QA evidence, and a clear roadmap.

## After Publishing

- Re-clone or download the public repository to a clean folder.
- Confirm no ignored/generated/private material appears in the public file list.
- Run the quick setup and at least one smoke launch from the clean copy.
- Verify every README link resolves on GitHub.
- Replace or add repository URLs in `pyproject.toml` only after the final public
  GitHub URL exists; never publish a guessed placeholder.
- Create GitHub issues only for real public follow-up work; keep private QA
  datasets and local machine notes outside public issue text.
