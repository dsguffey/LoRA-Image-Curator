# 0.7.2 selected-installation UX and qualification

The Manager previously started from its default or explicit root on every launch. Browsing to an existing LIC root called `inspect_selected_root` synchronously from Tk before updating the visible path. That inspection validates the installed environment and can scan provider resources, so the old path remained visible while the window appeared unresponsive. There was no durable pointer to the last successfully validated root.

The last valid root is now a small schema-1 JSON pointer at `%LOCALAPPDATA%\LICInstallManager\last-valid-root.json`. It contains only the absolute installation path. It is atomically replaced only after `inspect_selected_root` returns `ready` and the root-bound component snapshot has been prepared, or after a successful Core activation/managed move passes validation. Choosing or typing a path does not write it. A missing/invalid remembered path remains visible and the prior pointer is retained until another root validates. A manager shortcut's `--root` is a fallback behind the remembered root; explicit roots for `--launch` and non-manager operations still take precedence.

Startup and Browse immediately display the selected path with an indeterminate “Validating existing LIC installation…” state. A generation and selected-root identity guard discards stale worker results. Core/provider actions, Import, Browse, and Launch are disabled or guarded during validation. The validation worker performs Core inspection, provider/model reconstruction, resource checks, and remaining-download checks. Tk receives a prepared snapshot and rebuilds the page once with the active Core card as its viewport anchor; heartbeat text changes without rebuilding it. Provider operation progress retains the prior six-stage and indeterminate behavior.

This release candidate does not change the approved `2026-09-26.1` compatibility profile or provider identities. The external laptop must still verify immediate Browse painting, responsiveness, path persistence across relaunch, provider reconstruction, and controls after valid and invalid selections. Full dual-level progress, Move/cleanup for external provider environments, and broader cosmetic work remain deferred.
